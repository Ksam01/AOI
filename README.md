## 1 项目概况

### 1.1 背景和基础

#### 项目灵感

据世界卫生组织统计，全球约有 **2.85 亿**视障人士，其中完全失明者约 3900 万，而中国是全球视障人口最多的国家，超过 **1700 万**。视障人士在日常出行中面临三大核心痛点：

1. **盲道导航困难**：盲道被占用、中断、磨损等问题普遍存在，且盲道无法提供前方障碍物、转弯等动态信息；
2. **过马路风险极高**：缺乏斑马线识别和对齐能力，无法判断红绿灯状态，过马路对视障人士是最高危的场景之一；
3. **物品查找无助**：在室内或户外环境中，视障人士无法快速定位所需物品（如饮料、药品等），日常自理能力受限。

与此同时，**多模态大模型**（视觉-语言-语音）和**实时目标检测**技术在过去两年取得了突破性进展。YOLO 系列分割模型、开放词汇检测（YOLO-E）、MediaPipe 姿态估计、阿里云 Paraformer 实时语音识别、Qwen-Omni-Turbo 端到端多模态对话等技术的成熟，使得构建一个**低成本、高可用的视障导航辅助系统**成为可能。

本项目"灵眸·顺耳"由此诞生——以**普通手机摄像头+麦克风**为感知终端，以消费级 GPU 为算力基础，以多模态 AI 大模型为智能核心，为视障人士提供从盲道导航、过马路辅助到智能寻物的**全场景出行解决方案**。

#### 已有工作基础

项目已完成了 **v1.0.0 版本**的原型系统开发与开源发布，具备以下成熟模块：

- **盲道导航系统**：基于 YOLO 分割模型的实时盲道检测，支持光流稳定的掩码跟踪、多项式拟合的中心线提取、转弯检测与避障规划；
- **过马路辅助系统**：斑马线感知监控（四级分层：发现→靠近→接近→到达），HSV+YOLO 双模红绿灯识别（多数表决+去抖），斑马线方向/对齐引导；
- **物品查找系统**：基于 YOLO-E 开放词汇检测（支持任意物品名称输入），MediaPipe 手部关键点追踪，光流物品追踪，手部引导与抓取检测；
- **实时语音交互**：阿里云 DashScope Paraformer 流式 ASR + Qwen-Omni-Turbo 多模态对话，支持热词打断、上下文感知的智能指令解析；
- **多终端支持**：FastAPI WebSocket 服务架构，桌面浏览器 + 手机浏览器均可接入，手机端利用 DeviceOrientation API 提供姿态感知。

项目代码已开源（采用 MIT 许可证），配备完整的技术文档（README、项目结构说明、安装指南、贡献指南等），支持 Docker 一键部署。

#### 团队构成

团队由具备计算机视觉、深度学习、嵌入式系统和前端开发背景的成员组成，拥有丰富的 AI 应用落地经验。

### 1.2 场景和价值

#### 适用场景

| 场景 | 描述 | 系统功能 |
|------|------|---------|
| **日常盲道出行** | 视障人士在城市盲道上行走 | 实时盲道检测、方向引导（左转/右转/平移/直行）、障碍物预警、急转弯提前提醒 |
| **过马路** | 到达路口需要通过斑马线 | 斑马线发现→对齐引导→红绿灯识别→安全通行提示→过完马路回归盲道 |

#### 社会价值

1. **提升视障群体出行自主性**：将视障人士从"依赖他人陪同出行"中解放出来，显著提升生活质量和独立生活能力；
2. **降低辅助成本**：利用现有手机硬件+开源软件，免去数万元的专用设备或导盲犬训练费用，普惠数千万视障人群；
3. **推动无障碍城市建设**：系统的斑马线/红绿灯识别能力可作为城市无障碍设施的"一致性检测"工具，辅助政府优化无障碍环境；
4. **技术赋能助残公益**：开源 MIT 协议允许公益组织、科研机构自由使用和改进，形成技术助残的社区生态。

## 2 项目规划

### 2.1 整体目标

参赛期间，本项目的整体目标分三个阶段推进：

**第一阶段：系统稳定性与体验优化（前1/3赛期）**

- 优化实时推理延迟：将端到端处理延迟从当前 ~200ms 降至 **100ms 以内**（利用 TensorRT 推理加速、模型量化）；
- 完善离线模式：将 ASR 替换为本地 Vosk/Whisper 模型，实现无网络环境下基础语音识别；
- 增强鲁棒性：通过更多真实场景数据（不同光照、天气、盲道材质）提升 YOLO 分割精度；
- 手机端体验优化：优化 Web 前端适配、降低带宽消耗、增加触觉反馈（振动提示）。

**第二阶段：功能完善与场景扩展（中1/3赛期）**

- 完善红绿灯检测：从当前的 HSV+YOLO 双模方案升级为专用红绿灯检测模型，支持行人信号灯（人形红绿灯）和倒计时识别；
- 增加室内导航能力：利用视觉SLAM/VIO 实现室内位置估计和无盲道场景下的路径规划；
- 公共场所寻物引导：扩展 YOLO-E 的文本提示库，支持200+常见物品，增加货架/桌面上的物体空间关系描述（"红牛在桌子的左边"）；
- 多模态危险预警：融合视觉+音频分析，识别车辆鸣笛方向、人群密集区域、施工区域等危险场景。

**第三阶段：可展示原型与初步验证（后1/3赛期）**

- 产出可对外演示的**完整原型系统**：包含桌面端+移动端+管理后台的完整产品形态；
- 在视障人士社区/机构进行 **≥5 人实景测试**，收集真实反馈并完成一轮迭代；
- 输出**技术白皮书**和**部署指南**，使任何具有基础技术能力的公益组织能够自行部署和使用；
- 探索与地方残联/视障人士协会的合作可能，推动试点应用。

### 2.2 技术创新点

#### 核心技术对比

| 技术方向 | 现有方案 | 本项目方案 | 创新点 |
|---------|---------|-----------|--------|
| **盲道检测** | 基于颜色阈值/传统图像处理 | YOLO分割 + Lucas-Kanade 光流稳定 + 多项式拟合中心线提取 | 多帧融合的多项式系数时间平滑（EWMA），大幅减少抖动；实时遮罩级光流跟踪，TinyObj/MOT 级别的轻量化跟踪 |
| **多模态融合决策** | 单一模块独立决策 | NavigationMaster 分层状态机（11个状态） + 语音优先级仲裁系统 | 将盲道导航、斑马线感知、障碍物检测、红绿灯识别统一到状态机框架下，通过优先级仲裁（障碍物100>斑马线80>方向50>直行10）避免多源指令冲突 |
| **过马路辅助** | 仅斑马线识别 | 四级斑马线感知 (discover→approaching→near→arrival) + 遮挡检测 + 红绿灯多数表决 | 首创盲道-斑马线联合感知，自动判断盲道是否遮挡斑马线；8帧多数表决红绿灯状态，避免闪烁导致误判 |
| **物品查找** | 需预定义物品类别 | YOLO-E 开放词汇检测 + MediaPipe 手部21点追踪 + 光流目标追踪 | 任意中文物品名输入，自动翻译为英文检测标签；手部-物品联合时空推理，引导手靠近物品并检测抓取完成 |
| **语音交互** | 单一语音模型 | Paraformer 流式ASR + Qwen-Omni-Turbo 多模态对话 + 热词打断 | 支持"停下""别说了"等热词即时打断，不清洗对话历史直接复位；上下文感知过滤无效指令 |
| **系统架构** | 单设备/单模型 | FastAPI WebSocket 多客户端 + NavigationMaster 状态机 + 多模型协同 | 桌面/手机双端Web接入，手机摄像头通过浏览器直接推流（无需安装APP）；多模型池化共享，GPU显存占用优化 |
| **去可视化干扰** | 画面上叠加大量标注 | 完全移除标注叠加，仅保留指令按钮 | 专为视障人士设计的"纯净"画面输出，避免视觉干扰，仅通过语音传递信息 |

#### 主要技术创新点总结

1. **分层状态机多模态融合**：设计了 NavigationMaster 统领器，将盲道导航、过马路、红绿灯检测、障碍物避障、物品查找等模块统一编入 11 状态的有限状态机，通过冷却期防抖、多数表决平滑、语音优先级仲裁等机制，有效解决了多传感器指令冲突和决策抖动问题；

2. **"盲道-斑马线"联合感知与无缝切换**：首创盲道导航过程中持续感知斑马线的方式（CrosswalkAwarenessMonitor），在盲道导航过程中实时检测斑马线面积变化并播报方位，实现盲道→斑马线→过马路→回归盲道的全流程无缝衔接，无需用户手动切换模式；

3. **开放词汇的"即说即找"寻物系统**：利用 YOLO-E 开放词汇检测能力，用户只需说"帮我找一下红牛"，系统自动将中文物品名映射到英文标签并启动检测；结合 MediaPipe 手部关键点追踪和光流目标追踪，实现从检测→锁定→居中引导→手部引导→抓取确认的完整闭环；

4. **低成本、零安装的多终端架构**：基于 FastAPI + WebSocket 的 Web 服务架构，手机用户仅需浏览器扫码即可开始使用（利用 WebRTC/WebSocket 推送摄像头画面），无需安装任何 APP，极大降低了视障人士的使用门槛。

## 3 实施方案

### 3.1 技术可行性分析

#### 数据采集方案

| 数据类型 | 采集方式 | 当前状态 | 扩充计划 |
|---------|---------|---------|---------|
| **盲道分割数据** | ModelScope 开源数据集 + 自行标注 | 已有 YOLO 分割模型（yolo-seg.pt），在标准盲道场景下 mIoU > 85% | 采集不同材质（橡胶/石材/金属）、不同光照、不同磨损程度的盲道数据 ≥ 500 张 |
| **斑马线/红绿灯数据** | 公共数据集（COCO、Mapillary）+ 实拍 | 已有斑马线模型（YOLO-E 开放词汇）+ HSV 红绿灯回退方案 | 采集中国城市特色斑马线、行人信号灯数据 ≥ 300 张 |
| **物品检测数据** | 自有标注 + YOLO-E 预训练权重 | 已有 shoppingbest5.pt（5类物品）和 YOLO-E 开放词汇（80+类） | 扩充至 200+ 日常物品类别 |
| **语音数据** | 阿里云 Paraformer 云端 ASR（无需自有数据） | 流式ASR已接入，中文普通话识别准确率 > 95% | 评估 Vosk/Whisper 离线方案 |
| **用户测试数据** | 系统自动录制（音视频同步） | 录制功能已就绪（AVI+WAV） | 在遵守隐私法规前提下，收集 ≥ 100 人次真实场景测试数据 |

#### 行业知识获取

- **视障出行需求调研**：通过视障人士社群、残联、导盲犬培训机构等渠道获取真实需求和场景痛点；
- **无障碍设计标准**：参考《无障碍设计规范》（GB 50763-2012）、《盲道设计规范》等行业标准；
- **红绿灯标准**：参考《道路交通信号灯》（GB 14887）中关于行人信号灯的形状、颜色、时序规范；
- **AI 辅助技术前沿**：持续跟踪 CVPR/ICCV/ECCV 中的视觉导航、多模态感知、开放词汇检测等方向的最新进展。

#### 算力与硬件可行性

- **本地 GPU 推理**：YOLO 分割 + YOLO-E 检测 + MediaPipe 手部检测，在 NVIDIA RTX 4060（8GB）上实测总推理延迟 **60-120ms**，满足实时导航需求（目标 ≤ 200ms）；
- **云端 ASR+TTS**：阿里云 DashScope Paraformer 流式延迟 **300-800ms**，Qwen-Omni-Turbo 首次响应 **1-3s**，在可接受范围；
- **手机端负载**：手机仅负责摄像头推流和音频播放，不承担 AI 推理，使用 3-5 年前的旧手机即可运行；视频推流带宽约 200-500KB/s（JPEG 640×480@15fps），4G 网络完全满足；
- **离线降级方案**：当网络不可用时，系统可降级为纯本地模式（YOLO检测 + 离线语音模板），核心导航功能不受影响。

#### 关键风险与应对

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|---------|
| GPU 资源不足 | 中 | 高 | 模型量化（INT8/FP16）、TensorRT 加速、降低推理分辨率 |
| 极端光照/天气下检测失效 | 中 | 中 | 多模态融合（IMU+视觉）、增加数据增强、图像预处理 |
| 手机摄像头视角限制 | 高 | 中 | 头戴/肩挂式支架设计指导、广角镜头适配 |
| ASR 网络延迟 | 低 | 低 | 离线 Vosk 模型备用、关键指令本地热词检测 |
| 隐私合规风险 | 低 | 高 | 本地处理为主、不上传原始图像、录制功能默认关闭 |

#### 核心模块技术详解

**1. 盲道导航 (workflow_blindpath.py)**

- **检测**：YOLO 分割模型（yolo-seg.pt）预测盲道二值掩码，类别 `class_id=1`，置信度阈值 0.20；
- **特征提取**：
  - 像素域方法：沿纵向逐行扫描，获取中心线点集 `{y, center_x, width}`，使用二次多项式 `poly_func(y) = a·y² + b·y + c` 拟合路径中心线；
  - 灭点法：对轮廓左右边缘分别拟合直线，计算灭点 VP 和中心线 L_center，用于方向估计；
- **稳定化**：多项式系数采用指数加权移动平均（EWMA）平滑（历史8帧，权重 0.7^n），有效抑制每帧检测噪声；
- **转弯检测**：滑窗法（窗口大小5）检测中心线方向角度变化，当相邻窗口角度差 ≥ 45° 时触发急转弯检测，需连续 3 帧确认后进入 MANEUVERING_TURN 状态；
- **避障**：障碍物检测白名单过滤（人/车/自行车等），按位置和面积计算危险度，触发语音预警（"前方有障碍物，停一下"）或避障引导（"路径被挡住，请向右侧平移"）；
- **状态子机**：ONBOARDING（上盲道，方向+位置两步调）→ NAVIGATING（直行导航）→ MANEUVERING_TURN（转弯处理，指令→等待平移→对准新路径）→ AVOIDING_OBSTACLE（侧移避障→向前通过→回归盲道）。

**2. 斑马线感知 (crosswalk_awareness.py)**

- **四级阈值分层**：

| 阶段 | 面积阈值 | 语音示例 | 重复播报间隔 |
|------|---------|---------|------------|
| discover（发现） | 1-8% | "远处发现斑马线，继续直行" | 不重复 |
| approaching（靠近） | 8-18% | "正在靠近斑马线，在画面左侧" | 每6.7秒 |
| near（接近） | 18-25% | "接近斑马线，在画面中间" | 每3.3秒 |
| arrival（到达） | ≥25% | "斑马线到了，可以过马路" | 每5.3秒 |

- **遮挡检测**：当盲道掩码与斑马线掩码重叠超过 30% 时，判定为遮挡状态，不触发"可以过马路"提示；
- **面积稳定性**：最近 5 帧面积变化需在 ±20% 以内，防止抖动误触发。

**3. 红绿灯识别 (TrafficLightDetector)**

- **双模方案**：
  - 优先模式：YOLO 模型检测红绿灯边界框 → ROI 提取 → HSV 颜色分类（红/绿/黄）；
  - 回退模式：图像上半部（0-50%高度）HSV 亮色团检测 → 最大连通域颜色判定；
- **多数表决**：最近 8 帧的颜色投票，取最高票作为输出，消除闪烁导致的误判；
- **绿色通行**：稳定绿灯检测且不在冷却期内时，自动触发过马路状态。

**4. 物品查找 (yolomedia.py)**

- **流程状态机**：
  - SEGMENT（检测）：YOLO-E 文本提示检测（用户中文语音→Qwen-Turbo 标签提取→英文标签），1秒自动锁定目标；
  - FLASH（闪烁确认）：锁定动画闪烁，确认追踪目标；
  - CENTER_GUIDE（居中引导）：语音引导将物品移到画面中心（"物品在您的左前方，请右转一点"）；
  - TRACK（手部追踪）：光流追踪物品位置 + MediaPipe 21 点手部关键点检测 → 判断手与物品的相对位置 → 方向引导 → 抓取检测（手指弯曲程度+物体与手重叠率）；
- **手部抓取检测**：通过手指尖（食指/拇指）与物品中心的欧氏距离判断是否接触，结合手指弯曲角度判断抓取完成。

**5. 语音优先级仲裁**

| 优先级 | 类型 | 示例 | 说明 |
|-------|------|------|------|
| 100 | 障碍物预警 | "前方有人，停一下" | 安全第一，最高优先级，始终播报 |
| 80 | 斑马线到达 | "斑马线到了，可以过马路" | 关键状态变化 |
| 60 | 红绿灯/过马路 | "绿灯稳定，开始通行" | 导航状态切换 |
| 55 | 斑马线接近 | "正在靠近斑马线" | 环境感知 |
| 50 | 方向指令 | "请向左微调""右转" | 导航引导，支持持续播报 |
| 30 | 一般指令 | "已对准新路径" | 状态确认 |
| 10 | 直行确认 | "保持直行" | 最低优先级，有限次数播报 |

- **播报冷却**：任意两条语音间隔 ≥ 1.2 秒，避免语音重叠；
- **方向持续播报**：同一方向指令支持每 3 秒重复播报（可配置），防止用户在调整过程中丢失方向感；
- **直行节流**：直行确认支持持续模式（每 4 秒）和限制模式（最多 2 次），避免过度打扰。
